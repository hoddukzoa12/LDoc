# 디자인 점검 결과

impeccable의 `audit`과 `critique`로 LDoc 화면 넷을 점검하고, 사람이 앱을 쓸 때 실제로 문제가 되는 것을 고쳤습니다. 화면 넷은 문서 선택, 단계별 양식, 양식 옆의 도우미 패널, 편집기와 옆 패널입니다. 화면의 성격은 Operate(사람이 앱에서 일을 끝내는 화면)로 보고 점검했습니다.

### 검출기

`impeccable detect --json`은 고치기 전, 중간, 고친 뒤 모두 `[]`, 종료 코드 0이었습니다. 스캔한 파일은 `src/App.tsx`, `src/FormScreen.tsx`, `src/AssistPanel.tsx`, `src/EditorScreen.tsx`, `src/Disclaimer.tsx`, `src/main.tsx`, `index.html`입니다. 평가 B는 일부러 문제를 심은 대조 파일로 검출기가 `.tsx`를 읽는다는 것을 확인했습니다. 소스에는 직접 쓴 색이나 크기가 거의 없고 모양은 Astryx와 테마가 런타임에 정하므로, 빈 결과는 화면이 깨끗하다는 뜻이 아닙니다.

## 발견한 문제와 처리

심각도는 critique의 P0~P3입니다. P0은 일을 끝낼 수 없음, P1은 큰 어려움이나 WCAG AA 위반, P2는 우회할 수 있는 불편, P3는 다듬기입니다. 근거의 화면 이름은 해당 판에서 `scripts/box e2e`가 만든 `e2e-out/` 파일입니다.
